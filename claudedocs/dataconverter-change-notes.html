01

인코딩을 json용과 C++용으로 분리

버그
+ private static readonly UTF8Encoding JsonEncoding = new(encoderShouldEmitUTF8Identifier: false);+ private static readonly UTF8Encoding CppEncoding  = new(encoderShouldEmitUTF8Identifier: true);

기존에는 세 파일 모두 Encoding.UTF8로 썼습니다. .NET의 Encoding.UTF8은 BOM을 붙입니다. 그런데 json을 읽는 쪽은 boost::json::stream_parser이고, 파서는 파일 맨 앞의 BOM(EF BB BF)을 공백이 아닌 쓰레기 문자로 보고 파싱에 실패합니다.

반대로 C++ 소스는 BOM이 있어야 안전합니다. 생성되는 .h/.cpp에 한글 주석이 들어가는데, MSVC는 BOM도 없고 /utf-8 플래그도 없으면 파일을 시스템 ANSI 코드페이지(949)로 해석합니다. 그래서 두 상수로 나눠 json은 BOM 없이, C++은 BOM 붙여 씁니다.

04

빈 셀 기본값의 박싱 타입 정확화

버그
- "int" or "long"     => (object)0,- "float" or "double" => 0.0,+ "int"    => 0,+ "long"   => 0L,+ "float"  => 0.0f,+ "double" => 0.0,

이 값들이 단순한 기본값이 아니라 C++ 타입 추정의 근거라서 중요합니다. 헤더 생성기는 rows[0] 값의 런타임 타입을 보고 int32_t/int64_t/float/double을 정합니다.

01

FNV-1a 64bit 해시로 CLASS_ID 발급

신규
+ private static long MakeClassId(string name)+ {+     ulong hash = 0xcbf29ce484222325UL;+     foreach (var b in Encoding.UTF8.GetBytes(NormalizeDataName(name)))+     {+         hash ^= b;+         hash *= 0x100000001b3UL;+     }+     return unchecked((long)hash);+ }

파일명과 int64_t 키를 잇는 방법이 필요했습니다. FNV-1a를 고른 이유는 알고리즘이 짧아 C#과 C++에 각각 똑같이 구현할 수 있고, C++에서는 constexpr로 컴파일 타임 상수가 되고, 상수값(0xcbf29ce484222325, 0x100000001b3)이 표준이라 나중에 누가 봐도 검증 가능하기 때문입니다. xxHash나 CityHash는 분포가 더 좋지만 라이브러리 의존성이 생깁니다.

unchecked((long)hash)는 ulong의 상위 비트가 켜졌을 때 OverflowException 없이 long으로 재해석하기 위한 것입니다. C++의 static_cast<int64_t>와 같은 비트 패턴을 얻습니다. 실제로 item의 해시는 2900776405502981158로 양수지만, 파일명에 따라 음수가 나올 수 있어 필요합니다.

+ private static string NormalizeDataName(string name)+     => Path.GetFileNameWithoutExtension(name).ToLowerInvariant();

+ file(GLOB_RECURSE STATIC_DATA_SOURCE ../StaticData/json/*.cpp)+ file(GLOB_RECURSE STATIC_DATA_HEADER ../StaticData/json/*.h)  …  add_executable(GAME_SERVER      ${GAME_SOURCE} ${GAME_HEADER} …+     ${STATIC_DATA_SOURCE} ${STATIC_DATA_HEADER}+ )

생성된 .cpp는 StaticData/json/에 있어서 GameServer/나 Engine/의 glob에 잡히지 않았습니다. 빌드에 들어가지 않으면 GlobalInitializer가 존재하지 않고, 프로토타입이 등록되지 않아 모든 CLASS_ID 조회가 실패합니다.

ENGINE 정적 라이브러리가 아니라 실행 파일에 직접 넣은 것이 중요합니다. 정적 라이브러리에서는 링커가 심볼 참조가 있는 오브젝트만 가져갑니다. item.obj는 아무도 이름으로 참조하지 않으므로(전역 객체의 부수효과로만 동작) 통째로 버려지고, 전역 초기화가 사라집니다. 링커 관점에서 완전히 합법적인 최적화라 경고도 없습니다. 실행 파일에 직접 컴파일되면 항상 남습니다.

세 가지가 바뀌었습니다. 첫째, 입력을 리프 폴더 XLSX\Item에서 루트 XLSX로 올려 모든 엑셀을 대상으로 삼습니다. 둘째, 시트명 Item을 뺐습니다 — 이제 첫 시트를 자동으로 씁니다. 셋째, 인자 순서가 입력 → 출력으로 바뀐 것에 맞췄습니다.

팀 세션이 보고한 예외의 표면적 방아쇠가 이 첫 인자였습니다. 다만 근본 원인은 인자가 아니라 디렉터리를 파일로 여는 코드(03번)였고, 이제는 어느 쪽 경로를 줘도 동작합니다.

남은 한 가지. float 컬럼의 첫 행이 비어 있으면 아직 double로 추정될 수 있습니다. 04번 수정으로 CastCell의 박싱은 정확해졌지만, 근본적으로는 엑셀 헤더의 타입 문자열(cost(float)의 float)을 스키마까지 전달하는 편이 맞습니다. 현재는 값의 런타임 타입으로 역추정하는 구조라 이 경로만 취약합니다.
